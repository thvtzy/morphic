- **String concatenation `++` in the spec language (finding F1 resolved)** — the user, as language owner, approved surfacing concat on 2026-11-21. `BinOp::Concat` existed in the AST, the IR interpreter (Strings and Lists), the Z3 verifier (`String::concat` / list extension), `expr_to_ir`, and the selector's IR type verdict — and the LLM prompt renderer already spelled it `++` — but the parser never produced it, so no spec could state a string assembly and every M3 template/walker/driver spec was blocked. `parse_expr_add` now probes `++` before `+` and builds `BinOp::Concat`: it shares the additive level (left-associative, multiplicative-level operands, tighter than comparisons — concat is the additive operation on its operand sorts, and the additive loop is the one place a two-character operator arm fits without a new precedence function), and `+` on numbers is byte-for-byte unchanged. The footprint is one parser production (the parser is char-level; there is no token enum to extend) plus one typechecker rule, so a rename stays cheap. The checker types Concat precisely, conforming to the sort-strict layers below: String++String is String; List<A>++List<B> is List<A> unless the element types are provably different (a coarse local mirror of `selector::provably_different`); Int, mixed, and mismatched operands are type errors at `morphic check` time instead of backend failures — while every other operator keeps the existing coarse rule, and since Concat was previously unparseable, no existing spec's check outcome changes. Decisive end-to-end test: the M3 wrap-one template `output == "Vec<" ++ inner ++ ">"` — a parse error before this change ("Expected expression" at the second `+`) — now yields a Z3-Verified equation seed that wins selection and executes through the interpreter at tpr 1.000, nested case included. One pre-existing emitter edge recorded with it: codegen renders IR Concat as Rust `+` and its string-ownership rewrite never fires on Concat operands, so literal-first assemblies render `(("Vec<" + inner) + ">")` (E0369 in Rust) while variable-first assemblies compile — the e2e test's compile leg runs on a variable-first fixture, and extending the ownership treatment to Concat operands is left to the M3 walker/driver emitter work. LANGUAGE_REFERENCE documents the operator (precedence 6, typing rules); the roadmap's F1 is marked resolved. Regression: all examples still pass `morphic check` (except the deliberately unfinished `functional_tokenizer.morph`, failing unchanged on its pre-existing record-syntax gap), and one pass each of the M2/M3 instruments is unchanged (M2 probe winners all Verified + ConstraintInduced, cross-validation golden 64/64 + sweep 539/539 per run; M3 probe seeds 28/28 per run, cross-validation golden 94/94 + pinned 301/301 per run)
