## [Unreleased]

### Added
- **M2 self-host specs** — `examples/self_host/validator.morph` (type checker lite: type-tag/node-kind domains, node arity table, lite tag compatibility, recursion depth guard) and `examples/self_host/printer.morph` (IR → text: type/kind/operator name lookups, parenthesis precedence rule, line-width rule), written in the dialect the current parser + typechecker verifiably accept
- **M2 proof tests** — `tests/m2_proof.rs`: pure-Rust mirror implementations with golden tests for every spec test case (including the multi-input specs the spec test syntax cannot bind), plus end-to-end `morphic check` pipeline tests with negative controls; the e2e self-host suite now also covers both new spec files
- **M2 synthesis probe** — `src/m2_synthesis_probe.rs` (test-only): runs the real pipeline (synthesize → Z3 verify → select → codegen) per spec for all 14 M2 specs at opt level 1, the only LLM-free configuration (opt levels 2–4 fail with `LlmError` in the default build — locked in by a unit test). First synthesis run results, recorded in `ROAD_TO_SELF_HOSTING.md`: synthesis completes for 14/14 specs, the pipeline's Z3 stage reports Verified for 4/14 (candidate-independent verdicts — see roadmap root-cause notes), and 0/14 generated implementations compile yet (codegen identifier/match-expression defects, unfilled holes)
- **M2 cross-validation harness** — `src/m2_cross_validation.rs` (test-only, ignored; sibling of the synthesis probe): compiles each synthesized winner into a rustc runner binary, executes it, and compares its behavior against the `tests/m2_proof.rs` mirrors (coverage: all 14 specs) over every golden case — the in-spec tests plus the proof file's extra golden assertions — and a fixed documented input sweep per spec (539 pinned + 41 spec-silent cases per run), over 3 synthesis runs; the full agreement matrix lands in `target/m2-synthesis/cross-validation.md`, and the comparison mechanics are pinned by unit tests with hand-built agreeing/disagreeing winners. Measured: behavioral agreement is perfect exactly for the three Z3-verified winners (`node_arity`, `is_literal_kind`, `is_infix_kind`); the other tested specs' tpr-1.000 winners agree only at/near their tested points (String lookups cover only their tested rows — `type_tag_name` golden 3/6, `print_node_kind` sweep 2/8; range-spec wildcards fail on spec-determined inputs outside the tested range), and the two test-less specs' winners are semantically arbitrary (sweep agreement 4–96% across draws). The M2 gate checkboxes remain open on this evidence — full notes in `ROAD_TO_SELF_HOSTING.md`

### Fixed
- **Hole replacement walker** — `replace_at_path` (under `replace_hole`, used by MCTS expansion and rollout) implemented only the `Block` path step; holes under any other node kind (match arms, If branches, Let bodies, …) were silently left in place, so MCTS "completions" were still-holed clones of their parent and were never harvested. All `PathElem` variants are now walked.
- **MCTS seed-root harvest** — the MCTS built a single tree rooted at one random population member, so completions of the test-induced seed (the only candidate shaped by measured behavior) almost never entered the candidate pool. A second tree is now rooted at each holed test-induced seed. Measured effect (synthesis probe, 3 runs × 14 specs): winners measuring test-pass-ratio 1.000 went from 0/42 to 36/42 (every tested spec, every run; the rest are the two test-less specs at their neutral 0.5), winners at 0.000 from 29/42 to 0/42, and generated winners compiling under rustc from 0/14 to 1/14 per run — the remaining failures are type-blind wildcard fillings (E0308), the next fix in line. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Type-directed hole fillings** — `HoleRef` now carries the hole's `expected_type` (recorded by seed construction but previously unreachable: the ref held only a path), and `generate_hole_fillings` / `random_filling` draw from a per-type literal menu when it is known (Bool → true/false, Int → 0/1, String → `""`, List → empty list, …), with the spec tests' expected outputs added to the expansion menu. Types with no honest literal menu (named/generic, Option — the IR has no Option literal node —, Map/Set/Array) and all untyped holes keep the legacy menu exactly. Measured effect (probe, 3 runs × 14 specs): winner test-pass-ratio distribution unchanged (36/42 at 1.000, 0/42 at 0.000), generated winners compiling under rustc from 1/14 to **12/14 per run** — every tested spec now compiles; error classes across the 42 files fell from 37× E0308 + 2× E0069 to 9× E0308 (all in the two test-less specs, whose winners are whole-body type-wrong random trees — no seed, no truth signal) and 0× E0069/E0425. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Candidate return-type gate** — selection now checks whole candidate bodies against the spec's declared return type. A new conservative IR type inference (`selector::return_type_verdict`) claims a body's type only when certain (literals, agreeing collections/branches, Let/Block tails, parameter-typed Vars, `len`/List builtins, Typed nodes; a provably mistyped `return` anywhere also counts), and `select_best` excludes provably mistyped candidates whenever a matching or unprovable one exists — falling back to the old ranking, documented, only when every candidate is provably mistyped. Composite weights and scoring are untouched, and the tpr-1.0 winners on tested specs are unaffected (regression-tested). Measured effect (probe, 3 runs × 14 specs): winner tpr distribution unchanged (36/42 at 1.000, 0/42 at 0.000); compiles 12–13/14 per run — the gate works, but in ~half of draws a test-less spec's hole-free pool is uniformly mistyped (nothing sound exists to crown) and the commonest surviving shape is a loop-rooted body the inference is deliberately blind to, so the remaining gap is generation-side pool composition, not selection. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Codegen statement/tail emission** — Collections in statement position are now terminated (`vec![];`): the unterminated emission was a syntax error whenever a statement followed (still present in 2 of 3 probe runs after the gate). Genuine value positions route through the existing tail renderer instead: the function body (its value is the return value — bare-expression bodies like `(actual + expected);` no longer return `()`), and `If` branch / `Let` body positions, mirroring match arms. Statement-shaped bodies emit byte-identical code, so previously compiling winners are unchanged. Measured effect (3 fresh probe runs): the syntax/`;` error class is gone from all 42 winner files; remaining errors 6× E0308 (was 9×), 0× E0069/E0425. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Type-directed random generation** — fresh candidate bodies (the random seeds, the pool's foundation: MCTS completions inherit their root shape) are now generated in the context of the spec's declared return type, reusing the selection verdict's certainty rules: type-plausible root shapes, If/Match tails in the same type context, loops only as statements inside Blocks ending in a typed tail, Returns only around return-typed expressions, and a shape menu restricted to what the Rust emitter can actually render (no `Call`/`Index`/`Concat`/`Len` shapes, no constant-zero divisors). The legacy untyped generator is byte-for-byte unchanged for callers without a type context. Measured effect: seed bodies provably mistyped for their spec fell from 314/1000 (31.4%, verdict-checked over the M2 signatures) to **0/1000 — with 1000/1000 provably matching** — and the sound-pool premise for the two test-less specs became structural (60/60 synthesis attempts contain a hole-free non-mistyped candidate; was ≈0.53–0.7 per attempt). Probe (3 runs × 14 specs): winner tpr distribution unchanged (36/42 at 1.000, 0/42 at 0.000); generated winners compiling under rustc **14/14 in every run** (was 12–13/14), with 0 error instances of any class across the 42 files (was 6× E0308). The two test-less specs' winners are type-sound but still semantically arbitrary — they have no executable tests (the spec syntax cannot bind tuple test inputs), so no truth signal exists for them. Full notes in `ROAD_TO_SELF_HOSTING.md`.

- **Codegen emitter completeness** — the Rust expression emitter (`ir_to_rust_expr`) fell through to `/* UNSUPPORTED */` for 19 of the 28 `IRNode` variants (Hole, Block, Let, loops, Match, Return, Closure, Map/Filter/Fold/Sort, Alloc, Assign, Index, Loop, Break, StructDef, TryPropagate) and degraded `BinOp` Xor / `UnaryOp` Head/Tail/Init/Last to unparseable `UNKNOWN_OP`/`UNKNOWN_UNOP` operands; any of these in an If condition, operand, argument or Let value made the generated file unparseable. The match is now exhaustive (no wildcard — rustc guards completeness): every variant renders to a parseable expression (Hole → `panic!("Hole not filled")`, Index → `(c)[i]`, TryPropagate → `(e)?`, Xor → `^`, Head/Last index, Tail/Init slice, Block/Let/loops/Match/StructDef as block or native expressions, Return/Break parenthesized, Alloc → a loud `panic!` naming the shape), block-like expressions are parenthesized in condition/scrutinee positions, and Set/Map collections are fully qualified (`std::collections::…`, previously E0433 with no import generated). The `Call`/`Map`/`Filter`/`Fold`/`Sort` statement arms are now terminated with `;` (the Collection arm's Phase 11 hazard), with value positions routed through the tail renderer so bare bodies and match arms keep yielding their values. Measured effect (probe, 3 runs × 14 specs): winner tpr distribution unchanged (36/42 at 1.000, 0/42 at 0.000), compiles stay **14/14 in every run**, and the marker sweep is clean — 0 `UNSUPPORTED` / `UNKNOWN_OP` occurrences across all 42 winner files, 0 error instances of any class. Full notes in `ROAD_TO_SELF_HOSTING.md`.

- **Candidate-encoding Z3 verifier** — `verify_one` encoded only the spec's postconditions and never the candidate (`is_well_formed` was a stub returning `true`); boolean-valued subexpressions encoded to int 0 and any Or-rooted formula to `true`, so the verdict was decided by constraint syntax alone: guard-style (`||`) lookup specs "verified" every candidate, equation-style specs verified none. The verifier now symbolically evaluates the candidate body over the spec's parameters as free Z3 constants — mirroring the IR interpreter's evaluable subset (Int/Bool/String sorts, literal lists, match folded to `ite` chains) — and checks each postcondition with `output` bound to that expression. Encoders are `Option`-valued end to end: anything unencodable (body or constraint) yields the previously unreachable `Inconclusive`, never a silent Verified; holed bodies are `Malformed`; counterexamples carry real Int model values; the solver timeout is actually applied. Measured effect (probe, 3 runs × 14 specs): winner test-pass-ratio distribution unchanged (36/42 at 1.000, 0/42 at 0.000), compiles 14/14 (one 13/14 in 8 runs, also present pre-fix — draw variance). Verified winners went 12/42 → 9/42 and the set changed completely: the old set was `node_arity` + the three String lookups (a free pass from syntax); the new set is exactly `node_arity`, `is_literal_kind`, `is_infix_kind` — the winners that provably ARE their spec's predicate. The other tpr-1.000 winners are honestly refuted (they cover only tested rows; Z3 finds counterexamples in untested ones) or inconclusive (composition specs whose constraints call other specs). Full notes in `ROAD_TO_SELF_HOSTING.md`.

- **Refutation gate in selection** — `verify_all` computed the full per-candidate `VerificationStatus` and discarded it, keeping only the collapsed `verified` bool, so selection could not tell a refuted candidate from an inconclusive one. `CandidateImplementation::verification_status` now records the verdict where `verify_all` computes it (pinned against `verify_one`), and `select_best` carries a third gate, after the completeness and return-type gates: a candidate whose recorded verdict is `VerificationFailed` cannot win while any survivor is unrefuted (Verified, Inconclusive, Malformed, or unverdicted), with the usual documented fallback when every survivor is refuted, and deliberately no Verified-preference beyond excluding the refuted. Measured effect (probe + cross-validation, 3 runs each): refuted winners 21/42 → **0/42** (winner verdicts: 9 Verified — the same three specs as before — and 33 Inconclusive), and the three verified specs keep perfect cross-validation agreement while the two composition specs (all-Inconclusive pools) are unchanged. But pool-level instrumentation (new probe fields) shows no Verified candidate reaches the pool for 11 of 14 specs in any run, so for the range/lookup families the gate crowns Inconclusive junk instead: winner tpr distribution 36/6/0 → 15× 1.000 / 7× 0.500 / 12× 0.000 / 8 partial, and cross-validation agreement falls (golden 52/51/51 → 29/23/29 of 64; String lookups agree nowhere — their new winners return `""` for every input). The gate is kept, not reverted: it makes "no winner is Z3-disprovable" true, and it is the mechanism that will crown spec-exact candidates once constraint-derived seeds (the recorded next blocker) put them in the pool. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Cross-validation runner timeout** — the harness executed each winner binary with no time limit, which was safe while winners were always-terminating per-test matches. With the refutation gate, loop-bodied Inconclusive candidates win pools, and a `while true` winner hung a measurement run for ~54 minutes at 100% CPU. Runners now execute under a 10s deadline (stdout to file, kill on expiry) and a timeout is recorded as total disagreement for the run — the harness's standing semantics for "fails to run" — pinned by a mechanics test with a non-terminating hand-written winner. The same measurement pass recorded both previously known execution defects recurring in fresh winners (E0689 `.abs()` on an ambiguous numeric literal; discarded statements computing trapping divisions/remainders that panic on legal inputs) plus 2 non-terminating winners — all recorded as next blockers, none fixed here.
- **Constraint-derived seeds** — the refutation gate could only crown what the pool contained, and no spec-exact candidate ever reached the range/lookup/test-less pools (Verified pool count 0 for 11/14 specs in every draw). A new seed family in `seed_population` builds candidates from the spec's postconditions: an **equation seed** (a postcondition `output == <expr>` whose right-hand side converts whole via `expr_to_ir` and lies in the verifier's encodable subset — via the new `verify::body_is_encodable` predicate, the exact precondition `verify_one` needs — becomes a candidate whose body is that expression) and a **guard-table seed** (postconditions `<guard> || output == <literal>`, recognized by evaluation: exactly one output pin plus comparisons of the single Int parameter against constants, the pinned value being the unique integer falsifying every guard leaf; compiled to one match over the input with the typed-literal default as wildcard). Constraint seeds carry a distinct provenance (`ConstraintInduced`) and get the same final-pool protection as test-induced seeds. Coverage: equation seeds for the six equation specs plus both test-less specs (their first truth signal of any kind), guard-table seeds for `node_arity` and the three String lookups; the two composition specs get none (their equations call other specs and do not encode — skipped by the admission rule, not special-cased). Measured effect (probe + cross-validation, 3 runs each, second harness pass identical): Verified pool count ≥ 1 for 12/14 specs in every run; 36/42 winners ConstraintInduced and Verified with the tpr distribution restored to 36× 1.000 / 6× 0.500 / 0× 0.000 and refuted winners still 0/42; compiles 14/14 in every run; cross-validation golden agreement 29/23/29 → **64/64 in every run** and sweep pinned agreement 332/238/246 → **525/539 in every run** — twelve specs at full agreement (the test-less pair deterministically: `tags_compatible` 121/121, `needs_parens` 100/100), the only remaining disagreements being the two composition specs, unchanged at their Inconclusive ceiling. Full notes in `ROAD_TO_SELF_HOSTING.md`.
- **Verifier spec-to-spec calls** — the two composition specs (`validate_kind_tag`, `print_node_kind`) sat at an Inconclusive ceiling: their postconditions call other specs, no candidate for them could ever be judged, and their constraint seeds were skipped because the equation body — a call — did not encode. A shared resolver now answers what a call denotes: `SpecIndex` (the module's specs by name, held by the synthesis engine and by `Verifier::with_specs`) produces a callee's body from the same Phase 17 constructions its constraint seed uses — its first convertible equation body, or its guard-table match when it has no equation (`node_kind_name` is the case that matters). The verifier inlines by substituting already-encoded argument VALUES into a fresh callee environment — one helper (`sym_invoke`) shared by candidate bodies and postconditions, so a call denotes the same thing on both sides — under a visited-set cycle guard and a shared depth cap (8): cycles and over-cap chains are Inconclusive, never a hang or a guess. Seed admission resolves calls at IR level through the same index, so the admitted composition seed's body is the resolved callee body (the range check; the lookup match) — measurable by the interpreter, emittable by codegen standalone — and admission is judged by the new `body_is_encodable_with` in the module context. Standalone synthesis and registry-less verification behave exactly as before. Measured effect (probe + cross-validation, 3 runs each, second harness pass identical): winner tpr distribution unchanged (36× 1.000 / 6× 0.500 / 0× 0.000), refuted winners 0/42, compiles 14/14 in every run, and winners are now spec-exact for all fourteen specs — **42/42 ConstraintInduced and Verified** (was 36/42); cross-validation golden agreement stays **64/64 in every run** and sweep pinned agreement rises 525/539 → **539/539 in every run** (`validate_kind_tag` 11/19 → 19/19, `print_node_kind` 2/8 → 8/8) — the matrix has no spec-determined disagreements left. The M2 gate checkboxes are deliberately not ticked by this change; the gate decision is a separate step. Full notes in `ROAD_TO_SELF_HOSTING.md`.

Tests: 193 passed / 0 failed, 4 ignored (159 unit + 8 e2e + 21 M2 proof + 5 tokenizer proof; ignored: 2 e2e CLI tests requiring a full binary build, 1 synthesis probe, 1 cross-validation harness)

## [0.1.0] — 2026-06-09

### Added
- **Initial release** — Self-Synthesizing Programming Language
- `.morph` specification language (parser, AST, type checker)
- MCTS + Genetic Algorithm + LLM hybrid synthesis engine
- Z3 theorem prover integration for formal verification (SMT-LIB2)
- Multi-target code generation: Rust, C, WASM, Python, JavaScript
- CLI: `build`, `check`, `synthesize`, `init`, `lsp`
- 30+ IR node types for architecture-agnostic representation
- Pareto-optimal candidate selection
- Interactive synthesis mode with live dashboard
- Example specs: sort, binary search
- Full documentation: README, ARCHITECTURE, CONTRIBUTING

### Known Limitations
- Z3 integration uses subprocess (FFI bindings planned for v0.2)
- LLM integration requires external API or local model
- Template library is minimal (stub implementations)
- No self-hosting yet (compiler not written in Morphic)
- No WASM playground
- LSP is planned but not implemented
